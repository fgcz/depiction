# System tests

End-to-end runs of the `depiction_targeted_preproc` pipeline against real acquisitions,
checked against their own inputs. Run them with:

```bash
nox -s system_tests
```

They are **not** part of the default `nox` sessions. One of the two fixtures runs in CI; see
[Why only half of this is in CI](#why-only-half-of-this-is-in-ci).

## The two fixtures

Both are described in [`fixtures.py`](fixtures.py), which is the only place to touch when
adding or swapping one. A fixture whose files are absent **skips** with a message naming
what is missing and how to get it.

| Fixture | Size | Source | Panel |
|---|---|---|---|
| `mouse_kidney` | 59 MB | Public, MIT, DOI 10.5281/zenodo.1560646 — fetched by [`tests/real_data/fetch.py`](../tests/real_data/fetch.py) into `.test-data/` | [`panels/mouse_kidney.csv`](panels/mouse_kidney.csv), committed |
| `tonsil` | 1.26 GB | B-Fabric resources `2445579` / `2445566`, dataset `53798` — none of them in the repository | `inputs/panel.csv`, from that dataset |

To run the public one from a fresh clone:

```bash
uv run python -m tests.real_data.fetch mouse_kidney
nox -s system_tests
```

The tonsil's three files go in `inputs/`; the same list is in machine-readable form in
[`inputs/inputs.yml`](inputs/inputs.yml), and `inputs/.gitignore` keeps everything in that
directory untracked.

`fixtures.py` **imports** the public manifest from `tests/real_data/datasets.py` rather than
repeating its URLs and checksums, so there is one place where those live.

### The mouse kidney panel is not a biological panel

It is the twenty strongest well-separated peaks in that acquisition's own mean spectrum,
regenerated by [`panels/make_mouse_kidney_panel.py`](panels/make_mouse_kidney_panel.py). It
identifies nothing. It exists because a targeted pipeline needs reference masses that hit
signal — `CalibrationMethodConstantGlobalShift` takes a `nanmedian` over per-reference peak
distances, so a panel that finds no peaks yields a NaN shift and an output that is quietly
all background. The FGCZ panel could not be reused: it is B-Fabric dataset `53798` and is
not ours to publish.

## What is asserted

Nothing is pinned to a particular acquisition. Every expectation is read back out of the
work directory — the imzML's coordinate list, the standardized panel, the metadata the
pipeline itself exported:

- image geometry against the coordinate bounding box and the panel row count;
- channel names against the panel labels;
- the foreground mask against the acquisition's coordinate set, which is strictly stronger
  than the pixel *count* it replaced — a count is satisfied by the right number of wrong
  pixels;
- no NaNs, which is what a degenerate calibration produces;
- the OME-TIFF's physical pixel size against the exported `raw_metadata.json`;
- spectrum count and coordinates preserved from `raw.imzML` to `calibrated.imzML`, and no
  `IMS:1000052` invented along the way.

Until Phase G this file asserted `{"x": 128, "y": 137, "c": 118}` and `n_nonzero == 10131`,
copied from one run on the tonsil. Those four numbers are all still checked — the tonsil run
is what proves the derivations reproduce them — they are just no longer written down, which
is what made a second fixture possible at all.

## Why only half of this is in CI

`mouse_kidney` runs on every PR, in its own job so a pipeline run never sits in front of the
lint and unit-test feedback. The 59 MB download is cached on the hash of
`tests/real_data/datasets.py`.

`tonsil` cannot: it is 1.26 GB, it is not redistributable, and neither is its panel. It skips
in CI exactly as it does on any machine without the files. Keeping it is still worth it — a
large real acquisition with a real 118-marker panel is the better regression test, it just
cannot be the only one.
